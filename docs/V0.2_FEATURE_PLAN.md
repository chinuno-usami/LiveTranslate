# v0.2 功能实施计划

> 目标版本：v0.2.0
> 状态：已实施（`cargo fmt` / `clippy` / `test` 全绿；Windows 实机 SteamVR + VRChat 待验证）
> 涉及需求：
> 1. 输出内容在 SteamVR Overlay 上显示（视觉参考 OVR Overlay Translator 的语音翻译界面）
> 2. 输出内容通过 OSC 发送到 VRChat Chatbox 显示（多条合并 + 超长丢最早）
> 3. 同时处理多个输入源，每个输入源单独设置翻译开关；多源同时开启时输出带来源标识
> 4. 独立的设置页面（单独窗口），可编辑配置文件内的全部字段
> 5. 设置页支持多个配置档切换
> 附加：标准版 / Full 版双构建产物（见 §11、`docs/BUILD_FLAVORS.md`）

## 1. 背景与目标

### 1.1 现状

当前程序是「单输入源 → VAD 分段 → ASR → 翻译 → Tauri 透明浮窗字幕」的单流水线结构：

| 模块 | 现状 | 与本需求的冲突 |
| --- | --- | --- |
| `src/app.rs` | 一个 `run_pipeline` 只打开一个 `AudioCapture` | 无法同时处理多个输入源 |
| `src/subtitle/mod.rs` | `Subtitle { source, translated }`，无来源信息 | 多源输出无法区分来源 |
| `src/main.rs` | `PipelineControl` 只保存单个 runner/forwarder；`SharedState.config` 不可变 | 多源启停、设置页热更新都需要改造 |
| `src/config.rs` | 只有 `audio.device_name` 单设备；写回靠 `patch_toml` 逐行替换 | 无法表达 `[[audio.sources]]` 数组，无法支撑设置页全字段编辑 |
| `src/ui/*` | 仅主浮窗（`subtitle://update` 事件只带 `Vec<String>`） | 无来源标识、无设置窗口 |
| 输出 | 只有屏幕浮窗 | 缺 SteamVR、OSC 两条输出通道 |

### 1.2 本版本目标

- **O1 多源并行**：任意数量的「麦克风 / 系统回环」输入源并行识别，每源独立翻译开关、独立历史与去重。
- **O2 统一输出层**：一次字幕事件同时送到「桌面浮窗 / SteamVR Overlay / OSC」，三条输出互不阻塞。
- **O3 SteamVR 内可见**：在 VR 头显中显示与参考应用风格一致的字幕面板（半透明深色面板、原文小字 + 译文大字、渐隐、跟随头部）。
- **O4 VRChat 可见**：通过 OSC Chatbox 把字幕发进 VRChat，默认把最近多条字幕**合并成滚动字幕**（超出 144 字符时丢弃最早的一条），含限流、截断、多源标识。
- **O5 可配置**：独立设置窗口覆盖配置文件全部字段（含多源表格、密钥、`extra_body`、原始 TOML 兜底）。
- **O6 双构建风味**：CI 同时产出「标准版（无 SteamVR / 无 OSC）」与「Full 版（SteamVR + OSC）」；各平台原有标准包保持不变，Full 版单独作为 Windows 额外产物。
- **O7 多配置档**：设置页支持新建/复制/重命名/删除/切换多个配置档；切换后整份配置生效并自动重启采集。

### 1.3 非目标（v0.2 明确不做）

- VR 控制器交互（手柄开关翻译、框选 OCR 区域）。参考应用有，本项目留到后续。
- OCR 文字识别翻译（本项目只做语音）。
- SteamVR Dashboard Overlay / manifest 注册（`openvr` crate 未封装 `CreateDashboardOverlay` / Overlay Flags）。
- OSC 服务端（接收外部控制指令）。
- 逐源独立 ASR 后端/翻译模型（只允许逐源覆盖识别语言，后端与翻译服务全局共享）。
- 字幕历史持久化 / 导出（仍然只在内存）。
- 配置档云同步 / 自动导入导出（v0.2 只在本地 `profiles/` 目录管理）。

### 1.4 兼容性要求

- 旧 `config.toml`（只有 `audio.device_name`、无 `[output]` / `[[audio.sources]]`）必须能直接启动，行为与 v0.1.6 一致。
- 配置档为可选能力：未启用时仍以 `config.toml` 为准，旧版本可继续读写；首次启用只做非破坏性迁移（复制为 `profiles/default.toml`）。
- 不破坏现有快捷键、托盘、点击穿透、窗口几何持久化行为。
- macOS / Linux 上不因 SteamVR 依赖而无法编译（SteamVR 走可选 feature，运行时缺 feature 时给提示）。

## 2. 现状关键约束（实现前必须知道）

1. **OpenVR API 有线程亲和性**：所有 `IVROverlay` 调用必须在同一个线程内完成；不能从 tokio 任务里直接调用。
2. **`openvr` crate 0.9 依赖 `openvr_sys`**：需要 CMake + C++ 编译器，静态链接 OpenVR；使用 `ApplicationType::Overlay` 初始化。macOS 无 SteamVR 运行时，必须平台/feature 隔离。crate 目前只封装了 `create_overlay / set_visibility / set_width / set_curvature / set_opacity / set_raw_data / set_transform_tracked_device_relative / set_transform_absolute / is_dashboard_visible`，没有 Overlay Flags 与 Dashboard 创建接口。
3. **VRChat OSC Chatbox 限制**：目标地址默认 `127.0.0.1:9000`，地址 `/chatbox/input`，参数 `(string, bool immediate, bool notify)`；文本上限 144 字符；发送过快会被丢弃，需要客户端限流（建议 ≥1s 间隔）并只保留最新内容；换行不可靠，需展平。
4. **现有配置写入是“文本行替换”**：`AppConfig::update_value_in_file` + `patch_toml`，保留注释但不理解数组表，设置页必须换成 `toml_edit` 的结构化编辑。
5. **`SharedState.config` 是只读克隆**：要让设置页保存后立即生效，需要改成可写（`RwLock<AppConfig>`）并区分「热更新字段」与「需重启字段」。
6. **Tauri v1 + 静态 UI**：`build.withGlobalTauri = true`，没有前端构建链；第二个窗口用 `tauri.conf.json` 声明（`url: "settings.html"`、`visible: false`），或用 `WindowBuilder` 懒创建。关闭时用 `prevent_close + hide` 复用窗口。
7. **单源 VAD 已经是 CPU 热点**（Silero/ONNX）：多源会成倍增加推理负载，需要并发上限与去重设备校验。
8. **现有事件/命令面**：`subtitle://update`、`status://update`、`config://subtitle`、`notice://message`、`error://message`、`click-through://update`；命令见 `main.rs` `generate_handler!`。改造时要保持前端兼容（同版本一起更新）。

## 3. 总体架构

```
                    ┌──────────────── SourceSupervisor ────────────────┐
                    │  for each enabled source (spawn)                 │
                    │  ┌───────────── run_source(source_id) ──────────┐ │
  [mic:0]  ────────►│  │ AudioCapture → Resample → VAD segmenter      │ │
  [loopback:0] ────►│  │      → ASR (per-source language watch)       │ │
  [mic:1]  ────────►│  │      → Translate (per-source enable watch)   │ │
                    │  │      → SubtitleProcessor (per-source)        │ │
                    │  └───────────────┬──────────────────────────────┘ │
                    └──────────────────┼────────────────────────────────┘
                                       │ PipelineEvent::Subtitle{ id,label,.. }
                                       ▼
                              ┌─────────────────┐
                              │   Forwarder     │  (单任务，串行分发)
                              └────┬────┬───┬───┘
                                   │    │   │
                     Tauri event   │    │   │  OutputManager
                 (桌面浮窗 UI) ◄────┘    │   └────────────► SteamVR overlay 线程
                                        │                  (openvr + 文本渲染)
                                        └──────────────────► OSC 线程
                                                           (VRChat chatbox, 限流合并)
```

新增/改造的四大块：

1. **`src/output/`（新）**：统一输出层，`OutputManager` 持有 SteamVR / OSC 两个后台 sink，接口 `publish(snapshot)`、`set_source_context(active_sources)`、`shutdown()`；全部 `try_send`，永不阻塞流水线。
2. **多源流水线（改 `app.rs`）**：`run_source()` 为每个源一份完整流水线；`SourceSupervisor` 负责 spawn/停止/聚合状态。
3. **`src/config/`（重构）**：`mod.rs`（结构体）+ `writer.rs`（`toml_edit` 定点写入、多源数组、校验、原子替换）+ `schema.rs`（设置页字段描述）+ `profiles.rs`（配置档快照与切换）。
4. **设置窗口（改 `main.rs` / `tray.rs` / `tauri-ui/`）**：独立 `settings` 窗口 + schema 驱动表单 + 配置档工具条 + 输入源表格 + 原始 TOML 兜底。

### 4.2 兼容与迁移策略

- 反序列化：`AudioConfig` 增加 `#[serde(default)] sources: Vec<AudioSourceConfig>`；`sources` 为空时由 `effective_sources()` 合成单源：
  ```
  id = "default", label = "输入源", device = audio.device_name,
  enabled = true, translate = translate.enabled, language = ""
  ```
- `[output]` 缺失 → 默认全部关闭，行为与旧版完全一致。
- 保存设置时**不删除** `audio.device_name`（旧版本回滚仍可用），但以 `sources` 为准；设置页保存多源表格后写入 `[[audio.sources]]`。
- 配置优先级保持 `AppConfig::resolve` 现有逻辑不变。

### 4.3 校验规则（保存前执行）

- `sources[].id`：非空、≤32、`[A-Za-z0-9_-]`，全局唯一（重复直接报错，不静默改名）。
- 启用中的源不允许 `device` 重复（同一物理设备被两个流打开在 WASAPI 独占/某些后端会失败）；允许保存但启用时跳过并告警。
- `enabled` 且 `device` 必须能解析（保存时只做语法校验，运行期解析失败 → 该源 Notice，其它源继续）。
- 数值范围：`max_chars ∈ [8,144]`、`min_interval_ms ∈ [200,10000]`、`max_per_window ∈ [1,10]`、`opacity/curvature ∈ [0,1]`、`width_m ∈ [0.3,5]`、`font_size_px ∈ [12,96]`、`max_lines ∈ [1,8]`（SteamVR）/ `[1,9]`（OSC）。
- `output.osc.mode ∈ {rolling, latest}`；`separator` 非空且 ≤4 字符；`content ∈ {translated, source, both}`。
- `output.osc.target` 必须是合法 `host:port`。
- `output.steamvr.anchor ∈ {hmd, world}`。
- 颜色字符串：`#RGB` / `#RRGGBB` / `#RRGGBBAA`，否则报错。

### 4.4 配置档布局（Profiles）

```
<config_dir>/                 # macOS: ~/Library/Application Support/com.chinuno.LiveTranslate
  config.toml                 # 当前激活配置（唯一权威文件；现有 resolve/写入路径不变）
  config.toml.bak
  profiles.toml               # { active = "default" }（仅元数据）
  profiles/
    default.toml
    vr.toml
    stream.toml
```

- `config.toml` 始终代表当前激活档；切换 = 校验目标档 → 原子复制到 `config.toml` → 重新加载。
- 每次保存设置时镜像一份到 `profiles/<active>.toml`，避免崩溃/强退后快照过期。
- 首次启用（`profiles/` 或 `profiles.toml` 缺失）：自动创建 `default.toml`（从现有 `config.toml` 复制；无文件则写默认）与 `profiles.toml`；不删除、不重命名旧文件。
- 仅在使用用户配置目录时启用；`--config <path>` 或便携模式（exe 同级 `config/default.toml`）下禁用，并在设置页显示原因。
- 名称：1–40 字符，允许字母/数字/中文/`_`/`-`；禁止 `/ \ : * ? " < > |`、控制字符、首尾空格/点、`.`/`..`、Windows 保留名（CON/PRN/AUX/NUL/COM1-9/LPT1-9）。
- 单个配置档解析失败：列表中标 `valid = false` + 错误摘要，允许删除/查看，禁止切换。
- 配置档与构建风味无关：标准包也能切换包含 `output.steamvr` / `output.osc` 的配置档（字段被忽略但保留）。

## 5. 数据结构、事件与命令

### 5.1 字幕与事件

```rust
// src/subtitle/mod.rs
pub struct SubtitleLine {
    pub source_id: String,      // "mic"
    pub label: String,          // "麦克风"
    pub source: String,
    pub translated: String,
}

pub struct SubtitleState {
    history: VecDeque<SubtitleLine>,
    max_lines: usize,
    show_source: bool,
    label_mode: LabelMode,      // Auto | Always | Never
    active_labels: Vec<String>, // 当前在跑的源（用于 Auto 判定）
}

pub struct DisplayLine {
    pub source_id: String,
    pub label: Option<String>,  // None = 本次不显示前缀
    pub source: String,
    pub translated: String,
    pub text: String,           // 桌面/SteamVR 用的渲染文本（含前缀、可多行）
}

// src/app.rs
pub enum PipelineEvent {
    Subtitle(SubtitleLine),
    Notice { source_id: Option<String>, message: String },
    SourceState { source_id: String, running: bool, message: String },
}
```

标签规则（桌面浮窗 / SteamVR / OSC 共用一套函数，避免三处不一致）：

- `Auto`：`active_labels.len() >= 2` 时加前缀，否则不加。
- 前缀格式 `format!("[{}] ", label)`，仅加在该条字幕的第一行。
- OSC 文本：`label` 存在时 `"[麦克风] 译文"`；`content = "both"` 时为 `"[麦克风] 原文 | 译文"`。

### 5.2 Tauri 事件（前端 payload 变更）

| 事件 | Payload |
| --- | --- |
| `subtitle://update` | `{ entries: [{source_id,label,source,translated,lines:[string]}], text, active_sources: [{id,label,translate}] }` |
| `source-status://update` | `{ sources: [{id,label,running,translate,device,message}] }` |
| `output-status://update` | `{ steamvr: {available,enabled,connected,message}, osc: {enabled,last_sent_ms,message} }` |
| `config://subtitle` | 增加 `label_sources`、`max_lines` |
| 其他 | 不变 |

（`subtitle://update.lines` 改为结构化 `entries`；前端同版本更新，不做双协议兼容。）

```rust
    language_tx: watch::Sender<String>,
    running: bool,
    last_notice: Option<String>,
}
```

- 每源 `translate_tx` 独立：满足「每个输入源单独设置翻译开关」且热生效。
- `language_tx` 每源独立：全局语言切换时遍历所有源 `send()`；逐源覆盖优先。

## 6. 功能一：SteamVR Overlay

### 6.1 技术方案

| 关注点 | 方案 |
| --- | --- |
| OpenVR 绑定 | `openvr = "0.9"`（可选依赖），`unsafe { openvr::init(ApplicationType::Overlay) }` |
| 平台 | **Windows only**（评审确认）；Linux / macOS 统一编译为 stub，功能不可用但编译运行不受影响 |
| 文本渲染 | `cosmic-text`（系统字体扫描 + CJK fallback + 换行/对齐）+ 手工 RGBA 合成 + 圆角/背景绘制 |
| 上传 | `overlay.set_raw_data(handle, &rgba, w, h, 4)` |
| 面板定位 | `set_transform_tracked_device_relative(handle, HMD(0), matrix)`；`world` 模式用 `set_transform_absolute(Standing, matrix)` |
| 尺寸 | 固定纹理宽 1024px，高度按内容计算；`set_width(width_m)` + `set_texel_aspect(w/h)`，面板高度自动匹配 |
| 显隐/淡入淡出 | `set_visibility` + `set_opacity` 插值（30fps 动画线程内） |
| 构建 feature | `steamvr = ["dep:openvr", "dep:cosmic-text"]`，**不进 default**；仅 Windows 的 Full 包显式开启；标准包不包含该代码路径 |

### 6.2 线程模型

```
tokio 侧 (output/steamvr.rs::SteamVrSink)
  └─ std::sync::mpsc::SyncSender<SteamVrCommand>   // Update(OverlayFrame) / Visible(bool) / Shutdown
                                                          │ try_send，满则丢旧帧
VR 线程 (专用 std::thread)
  ├─ init / retry loop（SteamVR 未启动时每 N 秒重试，指数退避上限 30s）
  ├─ 持有 openvr Context + OverlayHandle + cosmic-text FontSystem + SwashCache
  ├─ 收帧 → 布局 → 光栅化到 RGBA → set_raw_data → set_opacity/transform
  └─ 30fps 循环：处理淡入淡出与 SteamVR 断开检测（调用失败则重建）
```

- 渲染放在 VR 线程内做：`FontSystem` 非 `Send` 友好，且避免纹理数据跨线程拷贝两次。
- `catch_unwind` 包裹 init 与单帧渲染：openvr 在无运行时/异常状态可能 panic，不能带崩主程序。
- 帧节流：内容变化才重渲染；字幕事件本身低频（VAD 句子级），无需额外节流，仅合并连续事件。

### 6.3 视觉规范（对齐参考应用的语音翻译界面）

参考 OVR Overlay Translator 商店页描述的「实时语音翻译字幕」形态：半透明深色浮板 + 原文小字 + 译文大字 + 多条向上堆叠。落地为：

```
┌──────────────────────────────────────────┐
│  ● 麦克风        英 → 中        2 源在线  │   ← 顶部信息行（12~14px，60% 白）
│                                          │
│  Hello everyone, welcome to the stream   │   ← 原文（16px，source_color，最新行 α=0.85）
│  大家好，欢迎来到直播间                    │   ← 译文（34px 粗体，纯白）
│                                          │
│  Are you ready?                          │   ← 上一条（整体 α=0.72）
│  准备好了吗                               │
└──────────────────────────────────────────┘
```

- 面板：圆角 24px（按像素换算）、背景默认 `#0B0F14` @ 80%、1px 内描边 `#FFFFFF14`，无阴影。
- 最新一条最亮，向上按 `line_alphas` 渐隐；空内容时整块淡出（`hide_on_silence_secs > 0`）。
- 多源时在每条译文前渲染小号圆角 chip（`label_color`），与桌面浮窗的 `[麦克风]` 语义一致。
- 位置：hmd 模式下正前方 `distance_m`、向下 `height_offset_m`；默认轻微偏下不挡视线。
- 面板整体 `opacity` 平滑过渡 120ms，出现/消失不突兀。
- 字体：使用**系统字体**（评审确认，不内置字体包）。优先 `font_path`，否则按候选列表找 CJK 字体（Windows `msyh.ttc` / `msyhbd.ttc` / `simhei.ttf`）；都找不到时降级为系统默认字体并 Notice「SteamVR 字幕可能缺中文字形」。

### 6.4 生命周期与容错

| 场景 | 行为 |
| --- | --- |
| 配置 `enabled = false` | 不启动线程；设置页打开时创建线程并尝试连接 |
| SteamVR 未启动 | 线程保持等待 + 退避重试；主界面状态显示「SteamVR: 未连接（等待 SteamVR）」 |
| SteamVR 中途退出 | 调用失败 → 隐藏/释放资源 → 回到重试循环；字幕内容保留在内存，重连后补一帧 |
| 停止采集 | 面板淡出隐藏（不销毁 overlay） |
| 退出程序 | `Shutdown` → `destroy_overlay` → 线程 join（带 500ms 超时） |
| 未编译 `steamvr` feature | 设置页开关置灰 + 提示「当前构建未包含 SteamVR 支持」 |

### 6.5 SteamVR 配置项

见 §4.1 `[output.steamvr]`。全部可在设置页修改；除 `enabled` 外均为热生效（重渲染/重设 transform）。

### 6.6 待实机验证点（写代码前先做 spike）

1. `openvr 0.9` 在 Windows runner 上能否顺利编译（CMake/C++），以及是否真的不需要附带 `openvr_api.dll`。
2. `set_raw_data` 的通道顺序（RGBA 还是 BGRA）——用纯色/文字实测，必要时启用 `swap_red_blue`。
3. `set_texel_aspect` 对面板高度的影响，确认动态高度方案可行。
4. HMD 相对 transform 的矩阵方向（OpenVR 列/行主序、-Z 前方），先用固定距离显示纯色面板验证。
5. 以 Overlay 类型初始化时 SteamVR 是否要求应用随 SteamVR 启动（是否需要在 SteamVR 中添加为非 VR 应用）；若必须，文档中说明启动顺序。

## 7. 功能二：OSC → VRChat Chatbox

### 7.1 协议

| 项 | 值 |
| --- | --- |
| 传输 | UDP，默认 `127.0.0.1:9000`（VRChat OSC 默认端口） |
| Chatbox | 地址 `/chatbox/input`，参数 `(string text, bool immediate=true, bool notify=false)` |
| 输入中 | 地址 `/chatbox/typing`，参数 `(bool)` |
| 库 | `rosc = "0.11"`（纯 Rust，`OscPacket::Message` + `encoder::encode`） |

### 7.2 组包：滚动合并（rolling）+ 限流 + 截断

VRChat Chatbox 一次可以显示一段多行文本（官方 Wiki：OSC 支持换行与自动换行，**最多 9 行**、**144 字符**），因此把最近几条字幕合并发送是可行的。

```
字幕事件（最终句）
  ──► 规范化单条：`[来源] 译文`（内容里的换行/连续空白展平为空格，单条内部不换行）
  ──► 入历史缓冲 VecDeque<Line>（条数上限 max_lines，超出从最早开始丢）
  ──► 组包：从最新往旧累加
         total = Σ(len(line) + len(separator))
         ├─ 加上下一条会超过 max_chars → 停止，**更早的消息直接被丢弃**
         ├─ 已收满 max_lines → 停止
         └─ 最新一条自身就超过 max_chars → 只截断这一条（保留头部 + "…"）
  ──► 与上次已发送文本比较：完全相同则跳过
  ──► 写入「最新待发槽位」（覆盖旧值，不排队）

OSC 线程：
  满足 min_interval_ms 且 5s 滑动窗口内发送数 < max_per_window
  → 取一次最新槽位发送；空槽/内容未变不发
```

- **历史缓冲不是发送队列**：组包结果覆盖旧快照，限流期间积压的是「最新的合并结果」，不是待发消息列表，避免延迟累积。
- 每次新句子都重新组包 → 老消息只在「放不下」时被挤出（符合“超过 144 字符丢弃最早一条”）。
- 示例（`max_lines = 4`，双源）：
  ```
  [麦克风] 大家好啊
  [游戏] 准备好了吗
  [麦克风] 我们开始吧
  ```
  继续来一条时，若总长会超 144 字符，则最上面的 `[麦克风] 大家好啊` 被丢弃后重发。
- 字符预算包含分隔符与前缀；按 Unicode `char` 计数（不切坏多字节，emoji/CJK 安全）。
- 评审确认：`mode = "rolling"`、`max_lines = 4`，采用**保守限流**（`min_interval_ms = 2000` + 5s 窗口最多 4 条）。
- 换行兼容：VRChat 历史上出现过 OSC 换行被 sanitize 的问题（2024 初反馈），当前 Wiki 明确支持换行。提供 `separator = "\n" | " | "` 配置；默认 `\n`，若实机发现被过滤改配置即可，不用改代码。
- `send_typing`：任一源有字幕活动 → `typing=true`；静音 `min_silence` 后 → `typing=false`。发送失败只记日志，不影响字幕。
- 发送目标变更（设置页）→ 直接替换目标地址（UDP 无连接）。
- 多源标识：每行都带 `[标签]`，合并后仍能区分来源；`content = "both"` 时单条为 `[标签] 原文 | 译文`（会更快吃掉字符预算，`max_lines` 自动少保留几条）。
- `mode = "latest"` 保留旧的单条行为，便于回退对比。

### 7.3 边界

- 无翻译（仅识别模式）时 `content = "translated"` 自动回退为原文，不发送空串。
- 历史为空或组包结果为空时不发送（避免误清空 Chatbox）；重复内容不重发。
- 最新一条自身超长：截断该条并加 `…`；`max_chars < 16`、`max_lines ∉ [1,9]`、`separator` 为空或过长直接拒绝保存。
- 不做「静音后自动清空」：VRChat 没有可靠的清空地址，最后一段会留在 Chatbox 直到被下一条替换。
- OSC 与 SteamVR 共用同一份 `DisplayLine`，不各自读配置，保证三种输出一致。

### 7.4 测试

- 纯函数单测：
  - 三种 `content` 组合 + 标签；
  - 滚动组包：全部放得下 / 超字符预算丢最早 / `max_lines` 上限 / 分隔符计入预算；
  - 最新一条自身超长 → 截断且不加更早消息；
  - 相同内容不重发；`mode = "latest"` 行文与旧行为一致；
  - Unicode 截断（emoji/CJK）、换行展平、限流时间戳与滑动窗口配额。
- 手工：VRChat 开启 OSC（Action Menu → Options → OSC → Enabled），连续说话验证 Chatbox 多行滚动、旧行被挤出、typing 指示、多源前缀；连续快速说话 10 秒观察是否触发客户端冷却。
- 手工：VRChat 关闭 OSC 时程序不报错（UDP 无回执，只能靠用户观察）。

### 8.2 运行时

```rust
// app.rs
pub struct SourceContext {
    pub id: String,
    pub label: String,
    pub device: String,
    pub language: watch::Receiver<String>,
    pub translate: watch::Receiver<bool>,
}

pub async fn run_source(
    base: AppConfig,           // 全局 ASR/翻译/VAD 配置
    source: SourceContext,
    tx: mpsc::Sender<PipelineEvent>,
    stop_rx: watch::Receiver<bool>,

```

- 每个源独立：`AudioCapture` / `LinearResampler` / `Segmenter`（VAD 或固定切片）/ `AsrEngine` / `SubtitleProcessor`。
- 共享：`OpenAiClient`（可 clone，内部 reqwest 连接池复用）、全局 `stop_rx`、`event_tx`。
- **失败隔离**：单源采集/ASR 失败只发送 `Notice{source_id}` 并结束该源；supervisor 记录状态，其余源继续。
- **任务模型**（v0.2 选择「全量重启」而非逐源热重启，降低并发复杂度）：
  - `start_capture_locked` → 启动 supervisor（JoinSet），对 `enabled` 的源各 spawn 一个 `run_source`。
  - 任一源配置变更（device/enabled/新增删除）→ 标记需要重启 → 执行一次「停止全部 → 启动全部」（约 0.3~1s，UI 显示「正在应用输入源变更」）。
  - 逐源翻译开关：只 `translate_tx.send()`，不重启。
  - 若后续需要逐源热重启，`SourceRegistry` 已按 id 拆分，可平滑升级。
- **并发上限**：`max_active_sources`（默认 4）；超出时只启动前 N 个并 Notice。启用 silero VAD 且源数 >2 时给出 CPU 提示。
- **重复设备**：启动前按 `device` 去重，重复项跳过 + Notice（不阻塞其它源）。

### 8.3 多源输出标识

- 桌面浮窗：`SubtitleState` 存 `SubtitleLine`，`entries[].lines` 已包含前缀；前端渲染时给来源加一个轻量 chip（颜色由 `id` 哈希到固定色板）。

- OSC：见 §7.2。
- 判定「多源同时开启」：`running && enabled` 的源数量 ≥ 2（不是 `sources.len()`）。

- 配置路径为 `None`（内置默认、无配置文件）时，首次保存前先 `write_default_if_absent(user_config_path)` 并更新 `config_path`。

### 9.4 多源表格（自定义组件）

- 列表行：`标签`（文本框）、`设备`（下拉，来自 `list_devices_command`）、`语言覆盖`（下拉，含「跟随全局」）、`翻译`（switch）、`启用`（switch）、`↑/↓`、`删除`。
- `＋ 添加输入源`：默认 id 自动生成（`source1`、`source2`…，冲突时递增）、label「输入源 N」、device 取默认设备。
- 删除/重排/修改后需要点「保存」才写文件；保存时统一提交整个数组（`toml_edit` 重写 `[[audio.sources]]` 段，保留其它注释）。
- 校验错误就地标红（id 重复/为空、设备重复、启用但设备不存在）。

### 9.5 原始 TOML 兜底

- Tab「原始配置」：`get_config_raw` 读取当前文件 → textarea（等宽字体）→ 保存时先 `toml::from_str::<AppConfig>` 校验，再写文件。
- 用途：`translate.extra_body`、未来新增字段、批量编辑。
- 保存后同样触发热应用 + `restart_required` 判断（通过比较新旧 `AppConfig` 得出）。

### 9.6 安全

- `api_key` / `trusted_client_token` 默认明文显示（评审确认允许回显），提供「隐藏」按钮；不做额外二次确认。
- 日志中继续走 `AppConfig::redacted()`，不打印密钥。
- OSC 默认只连本机；允许改 host 时在 UI 标注「跨机发送会暴露字幕内容」。

### 9.7 配置档（Profiles）

**目录布局**：见 §4.4。`config.toml` 始终是权威文件，配置档是它的命名快照。

**切换流程**

```
switch_profile(name)
  1. 若当前表单有未保存修改 → 前端提示「保存 / 丢弃 / 取消」
  2. 读取并校验 profiles/<name>.toml → 失败则中止（内存配置不变）
  3. 取得 state.lifecycle 锁（与启停互斥）
  4. 备份当前 config.toml → config.toml.bak
  5. 停止流水线（若运行中）
  6. 临时文件 + rename 原子替换 config.toml
  7. 解析 AppConfig → 更新 SharedState / SourceRegistry / 窗口几何 / 输出
  8. 写入 profiles.toml(active=name)
  9. 重启流水线（若切换前在运行）→ emit 全量事件
  任一步失败：用备份恢复 config.toml，保留旧内存配置，返回错误
```

- 切换等价于「整份配置替换」，**总是**需要重启采集；UI 在切换前明确提示。
- 新建默认从当前配置复制，可取消勾选生成默认配置；复制 = 新建一份当前快照。
- 删除 active 档直接拒绝；删除前二次确认（配置档文件不可恢复，除非用户自行备份）。
- 重命名只改文件名与 `profiles.toml` 中的 active（若重命名的是当前档）。
- 托盘菜单不提供配置档切换（避免与设置页状态双写）；后续需要再加。

**UI**

- 设置窗口顶部固定一条「配置档」工具条：`当前: [vr ▾]` + `新建` / `复制` / `重命名` / `删除` / `打开目录`。
- 切换时若流水线在跑，确认框注明「切换后将重启采集」。
- 切换成功后刷新全部表单、字幕样式、输出状态、输入源列表。
- 配置档禁用时（`--config` / 便携模式），工具条整体置灰并显示原因。

### 9.8 测试

- 单测：schema 中每个 `path` 都能映射到 `AppConfig` 字段（防止结构体改名后设置页悄悄失效）；`toml_edit` 写入后注释保留、数组增删正确、非法值不落盘。
- 单测（临时目录）：配置档迁移创建 default、创建/复制/重命名/删除、删除 active 拒绝、名称校验、非法目标拒绝切换、active 持久化、`--config` 下禁用。
- 手工：改字号/颜色即时生效；改 ASR base_url 提示重启；重启后新配置生效；关闭窗口再打开状态正确；主窗口点击穿透时设置页仍可用。
- 手工：运行中切换配置档 → 自动重启采集且显示新配置；切回原档内容一致；切换损坏档被拒绝且当前配置不变。

## 11. 依赖与构建

```toml
[dependencies]
toml_edit = "0.22"          # 保留注释的配置写入（所有包都需要）
rosc = { version = "0.11", optional = true }   # OSC，仅 Full 构建

[target.'cfg(windows)'.dependencies]
openvr = { version = "0.9", optional = true }
cosmic-text = { version = "0.19", optional = true }

[features]
# default 保持 ["custom-protocol", "silero-vad"]，标准包不包含 osc/steamvr
osc = ["dep:rosc"]
# 仅 Windows 支持 SteamVR（评审确认）；openvr-sys 需要 CMake + C++ 工具链
steamvr = ["dep:openvr", "dep:cosmic-text"]
# Windows Full 包：一次开启 OSC + SteamVR
extras = ["osc", "steamvr"]
```

> 版本号在实现时以 `cargo add` 实际解析为准；`cosmic-text` 与 `openvr` 均需在 Windows runner 上做一次编译 spike 再定版。
>
> 代码层：`src/output/osc.rs` 与 `src/output/steamvr/*` 用 `#[cfg(feature = ...)]` 选择真实实现或 stub（stub 返回 `available: false`），保证标准包不链接 `rosc`/`openvr`。`get_capabilities()` 用 `cfg!(...)` 上报能力，前端据此置灰入口。

### 11.1 发布风味（构建矩阵）

| 平台 | 产物 | features | 说明 |
| --- | --- | --- | --- |
| Windows x64 | `livetranslate-x86_64-pc-windows-msvc`（标准） | `custom-protocol` | **保留原有包**，与 v0.1.6 一致，无 SteamVR/OSC |
| Windows x64 | `livetranslate-x86_64-pc-windows-msvc-full`（Full） | `custom-protocol,extras` | 新增单独产物，SteamVR + OSC |
| Linux x64 | `livetranslate-x86_64-unknown-linux-gnu.tar.gz`（标准） | `custom-protocol` | 保留原有包；后续如需可加 `--features osc` 单独产物 |
| macOS universal | `LiveTranslate-universal-apple-darwin.zip`（标准 .app） | `custom-protocol` | 保留原有包；同上 |

- 两个 Windows 包都附带 `onnxruntime.dll`；Full 包若 spike 证实需要 `openvr_api.dll`，只放进 Full 包。
- 每个包内都放入 `docs/BUILD_FLAVORS.md`（重命名为 `BUILD_FLAVORS.md` 放包根），方便用户拿到包后直接看差异。

### 11.2 CI / release 改造

`ci.yml`：

- 现有三平台默认 `cargo check --all-targets` / `clippy` / `test` 保持不变（验证标准包）。
- Windows job 额外跑 `cargo check --features extras` 与 `cargo clippy --all-targets --features extras -- -D warnings`，确保 Full 风味不腐烂。
- Linux / macOS 可选跑 `cargo check --features osc`（OSC 本身跨平台，便于未来出单独产物）。
- 新增一步「标准包不包含可选依赖」：`cargo tree --features custom-protocol | grep -E 'rosc|openvr|cosmic-text'` 必须无输出。

`release.yml`：

- `matrix.include` 增加一条：
  ```yaml
  - name: windows-x86_64-full
    os: windows-latest
    target: x86_64-pc-windows-msvc
    features: custom-protocol,extras
    suffix: "-full"
  ```
  其它条目增加 `features: custom-protocol`、`suffix: ""`。
- 单目标构建步骤改为 `cargo build --release --features ${{ matrix.features }} --target ${{ matrix.target }}`；macOS universal 的两条命令保持 `custom-protocol` 不变。
- Windows 打包步骤用 `$suffix` 生成 stage 与 zip：`livetranslate-x86_64-pc-windows-msvc$suffix`；其余打包逻辑（ORT、config、README）复用，并把 `docs/BUILD_FLAVORS.md` 复制进包根。
- Linux / macOS 打包步骤同样追加 `docs/BUILD_FLAVORS.md`（标准版说明）。
- `release` job 的 `files: dist/*` 会自动收录两个 zip；在 git-cliff 生成 changelog 后再拼接 `docs/BUILD_FLAVORS.md` 作为 `body_path`，说明两个包的区别。
- `Verify tag matches crate version` 等现有校验不变。

本地脚本：

- `scripts/make-windows-package.sh` 保持「标准包」交叉编译路径（macOS 上无法构建 openvr-sys）。
- Full 包只在 Windows runner（或 Windows 本机）构建；可选新增 `--flavor full` 参数，在非 Windows 环境直接拒绝并提示走 CI。

打包体积影响：标准包体积不变；Full 包因 `openvr_sys` 静态链接 + `cosmic-text` 约 +3~5 MB，可接受；不内嵌字体。

## 14. 风险与备选方案

| # | 风险 | 影响 | 应对 / 备选 |
| --- | --- | --- | --- |
| 1 | `openvr-sys` 需 CMake + C++（已接受），或 CI/本地构建失败 | 阻塞 M3 | 先 spike；失败则改「运行时动态加载 `openvr_api.dll`」的薄 FFI（`libloading`，手写 vtable）或直接调用 `openvr_sys` 只做 Overlay 子集；再不行降级为「SteamVR 桌面镜像浮窗」并明确说明 |
| 2 | OpenVR 通道顺序/矩阵方向不确定 | 面板颜色反转/位置错 | `swap_red_blue` 配置兜底 + 纯色/网格调试面板；矩阵先用固定值实测 |
| 3 | SteamVR 未启动时 init 阻塞或 panic | 主程序卡住/崩溃 | 专用线程 + `catch_unwind` + 超时重试；`enabled` 默认关闭 |
| 4 | 多源并发导致 CPU 过载、ASR 排队丢段 | 延迟升高 | `max_active_sources`、重复设备校验、silero 源数提示、丢弃计数可见 |
| 5 | VRChat Chatbox 限流/144 字符/9 行 | 消息被吞、触发 30s 冷却 | 滚动合并（每句只发一次）+ 丢最早 + 5s 窗口内最多 4 条 + 字符截断；客户端无回执，只能保守限流 |
| 6 | Tauri v1 第二窗口 URL/生命周期差异 | 设置页打不开 | 配置声明式窗口（`url: "settings.html"`），关闭拦截隐藏；先做最小 demo 验证 |
| 7 | `toml_edit` 写入破坏用户注释/顺序 | 配置损坏 | 备份 + 写后重解析校验 + 失败回滚；单测覆盖 |
| 8 | CJK 字体缺失导致 SteamVR 方块字 | 不可用 | 使用系统字体（已确认不内置）；候选列表 + `font_path` 覆盖 + 缺字 Notice |
| 9 | 设置页 schema 与结构体漂移 | 字段编辑失效 | schema 全覆盖单测（§13） |
| 10 | 多源事件顺序/历史混排观感差 | 体验问题 | 已确定「单条时间线 + 来源前缀」；颜色 chip 区分来源，必要时主题可调 |
| 11 | macOS/Linux 上误触发 SteamVR 相关代码 | 编译/运行问题 | 平台 cfg + feature 双保险，stub 返回「仅 Windows 支持」 |
| 12 | 两个 Windows 包解压后同名/覆盖，用户下错包 | 功能不可用、困惑 | 产物目录与 zip 均带 `-full` 后缀；包内 `BUILD_FLAVORS.md`；应用内能力提示；Release 说明首段区分 |
| 13 | 标准构建误改 `output.*.enabled` 后以为已生效 | 无输出、误报 bug | 保存时拒绝 + 设置页置灰 + 启动日志/状态提示「当前构建不含该输出」 |
| 14 | 两个包共用同一配置文件 | 回退到标准包时旧字段不生效 | 配置段始终保留、`serde(default)` 宽容解析；标准包只忽略不删除 |
| 15 | 配置档与 config.toml 双份文件不一致 | 用户困惑、回滚丢设置 | `config.toml` 始终权威；保存时镜像；切换时原子替换；文档写清语义 |
| 16 | 切换配置档时崩溃/失败 | 配置损坏无法启动 | 备份 + 临时文件 rename + 解析校验后才替换 + 失败回滚 |
| 17 | 配置档名跨平台非法（Windows 保留名/分隔符） | 无法创建/删除 | 名称白名单 + 保留名过滤 + 就地错误提示 |

## 16. 评审结论与假设

### 16.1 已确认决策

| # | 问题 | 结论 | 对计划的影响 |
| --- | --- | --- | --- |
| 1 | SteamVR 平台范围 | **只保证 Windows** | `openvr/cosmic-text` 依赖只声明在 `cfg(windows)`；Linux/macOS 为 stub；仅 Windows 发布包带 `steamvr` feature |
| 2 | `openvr` 构建依赖 | **接受 CMake + C++** | 采用 `openvr 0.9` 静态链接；M3 先做编译与渲染 spike；薄 FFI 仅作失败备选 |
| 3 | 中文字体 | **系统字体** | 不内置字体包；候选列表 + `font_path` 覆盖 + 缺字 Notice；安装包体积不变 |
| 4 | 多源字幕布局 | **单时间线 + 来源前缀** | `SubtitleState` 用单一 `VecDeque` 按时间排序；不做分组布局 |
| 5 | OSC 合并策略 | **rolling，`max_lines = 4`，保守限流** | 默认 `min_interval_ms = 2000` + `max_per_window = 4`（5s）；保留 `mode = "latest"` 回退 |
| 6 | OSC 双地址 | **不需要** | 只保留单一 `target` + 可选 `custom_address`（同内容镜像），不做原文/译文分流 |
| 7 | 设置页 API Key | **允许明文回显** | `Secret` 字段默认明文 + 「隐藏」按钮；日志仍然 redacted |
| 8 | 发布产物形态 | **标准包保持不变，另出 Windows Full 包（SteamVR + OSC）** | `osc` / `steamvr` 均为可选 feature，`extras` 仅在 Windows Full 包启用；标准包不链接可选依赖 |
| 9 | 多配置档 | **设置页支持新建/复制/重命名/删除/切换，切换重启采集** | 新增 `profiles/` + `profiles.toml`；`config.toml` 保持为当前激活文件，现有 resolve 路径不变 |

### 16.2 未显式确认、按以下假设实施（可在实现前推翻）

| 项 | 假设 |
| --- | --- |
| SteamVR 默认开关 | 发布包默认 `[output.steamvr].enabled = false`，用户在设置页手动开启（避免非 VR 用户看到一个后台线程） |
| OSC 默认开关 | 默认 `false`，避免未经同意向本机 VRChat 发送数据 |
| 逐源 ASR 语言 | 保留 `language` 覆盖字段，默认留空 = 跟随全局；UI 仅在多源表格里提供下拉 |
| 多源并发上限 | `max_active_sources = 4`；超出按配置顺序取前 N 个并 Notice |
| 滚动历史时间窗 | v0.2 只用「字符预算 + `max_lines`」裁剪，不按时间过期 |
